# Identity database runtime separation

For a runtime-only deployment set `PLATFORM_IDENTITY_RUNTIME_ONLY=true` and `SPRING_FLYWAY_ENABLED=false`. Startup rejects this mode unless Flyway is explicitly disabled and all `PLATFORM_IDENTITY_FLYWAY_DATASOURCE_*` values are absent. Supply only the application role through `PLATFORM_IDENTITY_DATASOURCE_URL`, `PLATFORM_IDENTITY_DATASOURCE_USERNAME`, and `PLATFORM_IDENTITY_DATASOURCE_PASSWORD`. The runtime role needs schema usage and application table/sequence privileges, but no schema CREATE or Flyway history access.

For AWS RDS in ap-northeast-2, the image includes the official regional trust bundle at `/etc/platform/rds-ca-bundle.pem`, pinned by SHA-256 in the Dockerfile. Use a URL such as `jdbc:postgresql://<cluster-endpoint>:5432/app?currentSchema=identity&sslmode=verify-full&sslrootcert=/etc/platform/rds-ca-bundle.pem`. Review and update the bundle and checksum when AWS rotates CAs; other regions need their own bundle. Credentials must be injected as secrets.

Before starting a runtime-only task, execute migrations through a separately authorized phase with the migration role. That phase must retain the Java `IdentityLegacySchemaGuard`, Flyway migration, and `IdentityRuntimeSchemaPrivileges.reconcile` in that order, with the runtime role configured as the reconciliation target. Hibernate validates the resulting schema at runtime. This configuration does not itself provision roles, migrate the database, or authorize a deployment. Existing migration-enabled behavior remains available when runtime-only mode is not selected.
